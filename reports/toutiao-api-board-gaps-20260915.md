## Source-built-host follow-up and OH direct-link fix

The captured IME host above did not request `ohos.permission.GET_NETWORK_INFO`; root also could not use the OH NetConn service. A separately **source-built** and installed `org.westlake.sourcehost` HAP requested both `GET_NETWORK_INFO` and `INTERNET` and had granted states `[0,0]` (`0` is granted in the inspected OH bundle source). Its installed HAP SHA-256 `fea4e312ce3e29e297ac0aad3f2c13c29bb3f18a50ff034f0c1ae0cb7c291503` matched `source-closure/verify/out/source-window-host-connectivity-signed1/source-host.hap`. This gives a controlled caller for the real OH service without relabelling the captured IME host as source-built.

Under that source host, the prior helper (SHA-256 `c0cfb72f861be7f1ca880c3d54d7cf1eda296c224be9c033b76def728bf0b5b6`) reached `backend=oh-netconn`, netId 100, `wlan0`, and successful OH statuses, but the initial Android-facing snapshot had MTU 0 and 0/0/0 address/DNS/route counts. The same-PID inspection nevertheless found a complete view tree with 13 feed items behind the privacy dialog. Its isolated app report is `source-closure/verify/out/toutiao-api-shim-fixes-sourcehost-device49/device-report.json`; `source_ui_accepted=false` and `full_source_closure=false`.

The generic Westlake JNI fix merged as [westlake PR #3](https://github.com/a2hlab/westlake/pull/3), merge commit `cf73b436887e5ebba4ea69dac0a1dfa734d44997`. It supplements incomplete direct-OH link properties using the process-observed kernel routes **only when** the OH interface and observed route interface exactly match. It keeps the real OH handle, capabilities and metering. The rebuilt helper SHA-256 was `091fc804ffa6985f3e47ab05359892c56442e9ab1d70945a5e1ca6c7870aa491`, matching the live app child's helper hash. The framework staging report (`source-closure/verify/out/framework-oh-direct-links-device52/device-report.json`) SHA-256 `2ce6b5b0a7bd482e922af9ff422b23676f28253b3ce45197c156c6b7956fa484` reports `passed=true`, `full_stack_accepted=false`.

The new source-host app report (`source-closure/verify/out/toutiao-oh-direct-links-sourcehost-device53/device-report.json`) SHA-256 `eefe6d2fc97e096a8836a060abc6e172f33981d63be417a8480dd4fc7f8f3dc3` used the same unchanged APK SHA-256 `a1112a0c941f865847c2fab9138cf815735268fbfcd41d697412fb80992c7395`. Its child UID 20010056 showed `self_network_info=1`, OH status `rc=0/0/0/0/0`, real netId 100 on `wlan0`, MTU 1500, and 2/2/2 usable address/DNS/route counts. The settled same-PID view tree (`source-closure/verify/out/toutiao-oh-direct-links-sourcehost-device53-inspection3/view-tree.txt`) SHA-256 `eaafa9f949f52439734deb6fa568d61e92537796c6cf46c4d4dbb8b2816ac250` had 13 feed items and two fetched image drawables behind the still-open privacy dialog. This is direct-OH link evidence; it does not prove the uncached fallback path, callback loss/reconnect, configured proxy, consent/input acceptance, or full source closure. The two source-host launches occurred at different board epochs, so their timing is not a controlled performance A/B.

## Native-library trace and reached looper fix

The structured loader trace merged in ART-build PR #3 produced an exact-lock ledger for the stable targeted run (`harness-scan-20260914-toutiao-source44/results-api-oh-native-load-trace1/toutiao-oh-alooper-wake65.evidence.json`). It ingested 2,179 events, including 50 library events and 328 runtime registrations; 1,616 watched native contracts remained `not-observed`. The run used the unchanged APK, runtime lock `sha256:701785aa4f61727bd38fe14a7bedd3c7abc30084c4ea1b947778becea52b5287`, and traced `libart.so` SHA-256 `100983a8a5095f97dcd93fb84756bf39887b6773a4b9d8f03165503ae15fd6ea` (build ID `469c5dffd8bbb0983b79041f1252e482e19feb90`).

Correctly routing `libjato.so` and `libvcbasekit.so` into the Android namespace exposed a real boundary omission: the compact source-built `libandroid.so` did not export `ALooper_wake`, although the bridge backend already exported `wl_ALooper_wake`. Westlake [PR #4](https://github.com/a2hlab/westlake/pull/4), merge commit `aa0f714d93756a235d00a7a8121833fa96a35651`, adds the generic null-safe forwarder. The rebuilt source boundary (`source-closure/verify/out/webview109-source-boundary-looper-wake-candidate6`) packaged successfully, and its compact `libandroid.so` SHA-256 `1522a4aa9765f5be9bf0327d5df224f5bdf81d29dc7448d3b045868479e92295` exports the symbol.

The board validation (`source-closure/verify/out/toutiao-oh-alooper-wake-routing-device65`) then loaded both `libjato.so` and `libvcbasekit.so` successfully in the Android namespace. After an extended settle, the same child remained alive with no fatal signal, a complete decor view, 13 feed items, and four decoded images (`submitted=1`, `failed=0`). Its settled view tree SHA-256 was `95fa1c4291a2eb43e29b03f603ad9a90d5fa371d72de5e05c4fdb91765ae4a18`; the complete child stderr matched on host and board at SHA-256 `108ea2d0182768c34f98d2c6861b99b858f85e2f9e62b2c929b82ba0693b06e8`. The exact parent and child PIDs were stopped by identity after capture.

Two additional candidates were then routed one at a time. `libkeva.so` loaded successfully in `toutiao-oh-keva66`; after an extended settle the same child remained alive with a complete 13-item feed and decoded images. Its full stderr matched on host and board at SHA-256 `1ec990fc5720536c0b7d7f11b3a5e9fa65e6575089f32bb579538466337afbd4`, and its evidence ledger recorded 345 runtime-registered contracts. `libmetasec_ml.so` similarly loaded successfully in `toutiao-oh-metasec67`, resolving the reached `ASensorManager_getDefaultSensor` relocation through the existing source-built Android boundary. Its settled feed also retained 13 items and decoded images; its full stderr matched at SHA-256 `db53820cea98374dc9ef2dec6a0817c7f8877ff40ccb7c32b0ad48d9f98b19e9`, and its ledger recorded 316 runtime-registered contracts. Neither run had a fatal signal.

The combined `libkeva.so` plus `libmetasec_ml.so` configuration was validated separately as `toutiao-oh-keva-metasec68`. Both libraries emitted successful Android-namespace load events, the same child survived the extended settle, and the complete view tree retained 13 feed items with two decoded images (`submitted=1`, `failed=0`). The view tree SHA-256 was `36ab6faaf158a186928077a55f8d53c41f68e46502bd105998facdcc14b09ba6`; complete stderr matched on host and board at SHA-256 `1e1c4212f5d41dc4270fdfc9701337c2b325fcaafd11b3211ad8e124ee5d54fd`. Its exact-lock ledger ingested 2,168 events and recorded 344 runtime-registered contracts. Exact child, parent, and touch-forwarder PIDs were stopped by executable identity after each run.

Broader automatic namespace selection was rejected. Experimental runs did resolve additional relocations, but activating optional Lynx libraries led to a null-call `SIGSEGV`; therefore no automatic routing or OH-first fallback change was retained. Loader failures for `liblynxsecurity.so`, `liblynx_markdown.so`, `liblynx.so`, and `libanimax.so` remain candidates for separate feature and semantic validation. Their presence in a tolerated loader failure does not by itself establish a missing shim.
